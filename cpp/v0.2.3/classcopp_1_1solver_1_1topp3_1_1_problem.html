Detailed Description

Prepared TOPP3 problem descriptor.

Construction borrows a ConstraintsRef, owns a copy of a_linearization, infers idx_s_final, and immediately asks Rust to linearize third-order constraints into the underlying constraint cache. The owning Robot or Constraints object must outlive this problem and solver calls using it.

By default every third-order row of a station is linearized directly at a_linearization[k]. Passing a non-empty b_linearization selects adaptive anchoring (Rust LinearizationModeTopp3::GivenFeasibleAdaptive): each row is anchored where it is nearly active at the feasible state (a_linearization, b_linearization). This requires a_linearization and b_linearization to be the a and b of the same previously solved third-order profile, with equal length; a TOPP2 profile discretizes b differently and must not be used. Prefer it when a spans a wide range over the window, and especially when a can approach zero (around 1e-10): anchoring both rows of one axis at the same small a_linearization[k] cancels b and c and leaves a[k] <= 3 * a_linearization[k]. On profiles well away from zero the default direct linearization is cheaper and nearly identical.

constraints.ref(), profile.a, 0, boundary, 1, 1.0e-10, profile.b};
